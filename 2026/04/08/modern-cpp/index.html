ranges库

优化容器内数据处理

ranges库定义在std命名空间

std::views是std::ranges::views的别名

views本质上是一个多层嵌套的模板结构体，包括封装的原容器指针、具体管道操作对应的函数对象、根据管道操作自定义的迭代器。

定义视图，编译期时通过类型推导，产出一个嵌套模板类型；运行期时实例化该嵌套模板结构体。

访问视图，借助自定义迭代器，过滤出符合期望的数据

伪代码

惰性求值，故定义时不放入内存

投影

std::bind_front

c++20引入：

std::ref()

应用于泛型模板编程，若用于常规非模板函数通常编译失败

常被以下模板函数用于传参：
std::thread std::async
std::bind()
std::for_each() std::invoke()

复制消除

c++17后成为语言标准强制要求
主要针对纯右值、类型与返回类型相同的局部变量

RVO和NRVO是实现复制消除这一编译器优化技术的具体方法
Return Value Optimization(c++17要求) : 临时对象直接在接收者的内存中构造。
Named Return Value Optimization(c++17仍为可选优化) : 该局部变量直接作用于返回值

结构化绑定声明

c++17引入 语法：
auto [a, b] = std::make_pair(1, 2); //example
必须搭配auto使用。

移动语义

c++11引入

移动行为的触发：
若源对象是临时变量，移动就会自动隐式发生。若源
对象是具名变量，则必须通过调用std::move()直接请求转移

移动语义仅对含有动态资源（如堆内存、文件句柄）的自定义类类型有效，以避免深拷贝；
而存在移动构造函数但无动态资源的自定义类型，同样能触发，但无性能提升。

  • 移动构造函数的作用就是转移某一处资源的使用权

    std::move、右值引用、移动构造函数 三者协同合作实现移动语义

函数声明中的->

模板编程中，函数返回值类型依赖参数类型时，使用 -> 可将后置返回值类型

c++14及以上会自行推导，无需显式写出 ->及跟在后面的类型
