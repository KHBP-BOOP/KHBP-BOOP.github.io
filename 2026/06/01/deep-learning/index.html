torch.tensor对象.reshape(-1) 或 torch.tensor对象.view(-1)
创建形状为一维的张量

view()：
若张量在内存中连续存储（即is_contiguous()为true），则改变张量的元信息（形状和步长），返回该张量的一个视图，同时用一个新的标识符对应该视图。这两个对象指向同一块内存空间
若张量在内存中不是连续存储（例如执行了 transpose()、permute() 或 narrow() 之后），直接抛出RuntimeError

reshape()：对连续性没有要求。它会先检查张量是否连续
如果连续，行为等价于 view()（共享数据）
如果不连续，先申请一块新的连续内存，将原始数据拷贝过去，然后再返回这个具有新的元信息的张量的视图

前向传播、反向传播和计算图

可以调整但不在训练过程中更新的参数称为超参数（hyperparameter）。 调参（hyperparameter tuning）是选择超参数的过程。 超参数通常是我们根据训练迭代结果来调整的， 而训练迭代结果是在独立的验证数据集（validation dataset）上评估得到的

中间激活值（A）：是非线性空间的映射。它引入了非线性（如将负值置零、压缩到 0~1 之间），正是这个值赋予了神经网络“拟合任意函数”的能力

反向传播重复利用前向传播中存储的中间值，以避免重复计算。 带来的影响之一是我们需要保留中间值，直到反向传播完成。 这也是训练比单纯的预测需要更多的内存（显存）的原因之一

这些中间值的大小与网络层的数量和批量的大小大致成正比。 因此，使用更大的批量来训练更深层次的网络更容易导致内存不足（out of memory）错误

前向传播，按照计算目标函数值的依赖路径，计算出每个中间值，它们中的部分中间激活值保存在内存中；反向传播，按照相反方向，根据上一次前向传播的中间值结果，先沿计算图传播梯度，再得到目标函数对每个模型参数的导数，通过优化算法沿着梯度的反方向调整参数，从而使得目标函数值整体趋于降低，最终完成一次参数更新

encoder与decoder的输出

  • 都表示任一token语义

  • encoder：输入源序列，无因果掩码但包含用于忽略填充位 的 Padding 掩码，理解各token深层语义，重复多次。

  • decoder：多层encoder执行结束后，输入目标序列，流经因果掩码自注意力子层，此时各token的语义基于自身及其左侧上下文得出；随后在交叉注意力子层中，融合由encoder最终输出的完整上下文，得到深层语义，重复多次

多层encoder块执行结束后，再执行decoder块

每一层decoder的输出都包含任一token的多种语义且丰富程度且不断变深

输入源序列，无因果掩码（但包含用于忽略填充位 的 Padding 掩码）。采用双向自注意力机制（Bidirectional Self-Attention），使得各层 token 能够同时捕获左右双向的上下文信息，从而充分理解各 token 的深层语义

输入目标序列，在自注意力层（Self-Attention）引入了因果掩码机制（Causal Mask）。这确保了在训练阶段，目标序列中各 token 在当前层的表征仅能结合自身及左侧已生成的上下文信息，从而防止未来信息泄露（Data Leakage）。随后，Decoder 通过交叉注意力机制（Cross-Attention / Encoder-Decoder Attention），将自身的中间表征（作为 Query）与 Encoder 最终输出的完整上下文表征（作为 Key 和 Value）进行动态融合，从而实现基于源语言上下文的目标语言生成

交叉注意力，注意力的计算源来自两个地方，即融合encoder输出以及decoder掩码结果；

自注意力，注意力的计算源来自一个地方，即输入自身的序列。

原始transformer架构
推理过程 第一个输出token基于输入序列，之后的token基于输入序列以及生成的序列
训练过程 输入源序列、目标序列，输出包含“每个位置可能的token概率”的矩阵

注意力头

一个注意力头（Head）是由 Q, K, V 矩阵中特定的一组列向量组合构成的，它包含了所有 Token 在该子空间下的投影，相当于不同的滤镜或观察视角。

每个注意力头不需要看完整的 512 维特征，只需要看分给它的 64 维特征，并在该低维子空间内独立计算一套注意力权重。最后，所有头的观察结果（列）再拼接（Concat）起来，恢复成完整的 512 维向量。

Token 采样策略

  1. Greedy Decoding（贪心解码）
    每一步都选概率最大的 token
    优点是确定性强、速度快；缺点是容易陷入重复循环（同一个短语反复出现），生成内容单调。适合需要确定性输出的场景（如代码补全、格式化输出）。

  2. Temperature 缩放
    在 softmax 之前对 logits 除以一个温度参数 T
    温度值 效果

T<1（如 0.3） 分布变尖锐，高概率 token 更突出
T=1 原始分布，不做调整
T>1（如 1.5） 分布变平坦，低概率 token 被拉高
T→0 退化为 greedy decoding
T→∞ 退化为均匀分布，完全随机

  1. Top-K 采样
    只保留概率最高的 K 个 token，将其余 token 的概率置零后重新归一化
    Top-K 的问题在于 K 是固定的。有时候概率分布很集中（只有 2-3 个合理选项），K=50 就引入了太多噪声；有时候分布很分散（很多 token 都合理），
    K=50 又太限制了

  2. Top-P 采样（Nucleus Sampling）
    一种自适应的方案：按概率从大到小排列 token，累加概率直到超过阈值P（如 0.9），只在这个”核”内采样：
    优势在于自适应性：分布集中时自动缩小候选集，分布分散时自动扩大候选集。

  • 实际使用中，Temperature + Top-P 的组合最为常见，比如 temperature=0.7, top_p=0.9。
