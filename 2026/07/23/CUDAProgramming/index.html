LDGSTS

在能够减少寄存器使用量的同时，保证load操作持续进行

支持拷贝4、8、16 Bytes数据
4/8 Bytes的拷贝对应 L1 ACCESS
16 Bytes的拷贝对应 L1 BYPASS

数据应为对应字节数对齐，即根据运输的数据量（4/8/16B）使其对齐。最佳情况为128B对齐

LDGSTS命令在运输完成后需要提供一个信号，可以通过SMEM屏障、pipeline实现
由于CTA内每个线程之间借助LDGSTS命令进行的拷贝操作是异步的，所以当这些SMEM上的数据需要在CTA范围内被共享时，__syncthread() 是必不可少的

分离编译

全程序编译的模式下，将来自cu源文件的可执行文件嵌入主机端目标文件，然后经过主机端linker生成可执行文件
分离编译的模式下，将来自cu源文件的可重定向设备代码嵌入主机端目标文件，然后由nvlink设备链接器解析、链接，最后经过主机端linker生成可执行文件

两种模式的选择由nvcc命令选项 -rtx 控制（–relocatable-device-code）

CUDA 5.0及其之后的版本，在使用分离编译的情况下，可以像编写主机端代码一样，在CUDA代码中使用extern和static，此前在CUDA代码中extern会被忽略；使用static意味着可能存在多个同名的变量，不同于此前的通过名字区分变量，CUDA API通过地址区分

–compile 将源文件编译为目标文件
–device-c（–relocatable-device-code –compile） 将源文件编译为带有重定向信息的目标文件

硬件限制

Block 每维最大线程数 x:1024, y:1024, z:64
Block 内最大线程总数 1024
Grid 每维最大 Block 数 x:2的31次方−1, y:65535, z:65535
每个 SM 最大活跃线程数 2048（sm_80）/ 1536（sm_89）
每个 SM 最大活跃 Block 数 16~32（取决于架构）

注意：Block 内线程总数不能超过 1024，即 blockDim.x * blockDim.y * blockDim.z ≤ 1024

kernel启动与错误检查

Kernel 函数的约束：
返回类型必须是 void
不能使用可变参数（variadic）
不能是类的虚函数
不能递归（Compute Capability < 2.0，现代 GPU 均已支持）
参数通过值传递，指针必须指向设备内存

kernel<<<gridDim, blockDim, sharedMemBytes, stream>>>(args…);
参数 类型 必填 说明
gridDim dim3 或 int 是 Grid 中 Block 的数量
blockDim dim3 或 int 是 每个 Block 中线程的数量
sharedMemBytes size_t 否 动态共享内存大小（默认 0）
stream cudaStream_t 否 执行流（默认 0，即默认流）

warp

SM（Streaming Multiprocessor）以 Warp 为粒度调度执行。同一Warp内的threads在同一时钟周期内执行同一条指令（对应SIMT编程模型）

warp divergence

遵循SIMT范式的代码中出现分支路径且各个分支运行的线程数量不可忽略，出现算力浪费

Occupancy

同一 SM 上实际活跃的 Warp 数 / SM 理论支持的最大 Warp 数

cudaOccupancyMaxActiveBlocksPerMultiprocessor(
  &numBlocks,
  MyKernel,
  blockSize,
  0);

grid block cluster thread

当应用程序启动内核时，它会使用许多线程，通常是数百万个线程

一个线程块（Block）中的线程数量通常为32的倍数，最常见的大小为 128、256 或 512，最大1024
一个grid可能包含数百万个线程块，而执行该网格的GPU可能只有几十或几百个SM
CUDA 当前最多允许一个集群（Cluster）内有 8 个线程块

CTA（Cooperative Thread Array，协作线程数组）是thread block在PTX / 底层执行模型中的具体执行单元

原语

warp级原语

T __shfl_sync(unsigned mask, T var, int srcLane, int width=32);

mask 指定参与此操作的活跃线程掩码。

作用：确保只有掩码中标记为 1 的线程参与同步和数据交换。这通常直接使用 __activemask()（返回当前 warp 中所有活跃线程的掩码），以保证正确性和性能。

关键点：必须显式指定，否则可能导致未定义行为或性能下降（这是 Volta 架构后引入的安全要求）。

  1. T var（变量值）
    含义：当前线程提供的源数据值（待交换的变量）。

作用：如果当前线程是 srcLane 指定的源线程，它的 var 就会被广播给其他线程；如果不是源线程，var 只作为入参，但最终结果会被覆盖。

  1. int srcLane（源线程索引）
    注意：源线程需包含在Mask掩码中（即需为活跃线程）

  2. int width = 32（宽度，可选参数）
    含义：指定参与交换的子 warp 宽度（必须是 2 的幂次方，如 2、4、8、16、32）。
    作用：将 warp 逻辑划分为多个独立的子组，数据交换只在同一个子组内进行。

__shfl_down_sync(0xffffffff, val, offset);

GPU执行模型

线程数应远高于核心数或指令管线数
线程块数应数倍高于SM数（如果总 block 数量刚好能被一个完整 wave 的容量大小整除，那么波数是整数；否则就会出现小数或非整数波数，表示存在 partial wave，导致尾部效应tail effect，同时这通常意味着GPU资源利用率的下降，对于执行时间较短的kernel的影响尤其明显。对于高端 GPU，通常只有线程块少于 300 个的启动才需要检查尾部效应）

wave代表一个包含并行执行的线程的集合

request 由高层次内存发出，低层次内存处理
request类型不同，数据运输的起点终点不同。从低层次内存为起点，高层次内存为重点或相反。

硬件模型

以通用计算为目的的异构并行计算模型

单指令多线程（Single Instruction, Multiple Threads, SIMT）是专门为GPU设计的并行计算模式。在统一的指令流控制下，多个线程在不同的数据上并行执行相同的操作

该异构模型的host为CPU、device为GPU，CPU管理二者的资源、调度GPU执行工作
Grid 是由thread blocks组成的1D或2D或3D列阵，即thread blocks的集合
Block 是由threads组成的1D或2D或3D列阵，即threads的集合。Block的等价说法 - CTA
Thread

为了使并行计算具有灵活性，设计出grid、block、thread的层次结构，该层次结构以CTA为核心。

同一CTA中的所有threads必须在同一块SM上并行执行，位于不同CTA的thread则不一定能同时执行，保持并行执行的同时增加了在时间上的调度灵活性
shared memory、同步屏障进一步开发了这一概念
来自不同CTA的threads的执行时间不一定相同、不一定运行在相同SM上，所以每个CTA之间一定是独立的，不存在某一CTA中的thread依赖另一CTA中thread的运行结果的情况。同时，来自不同grid的threads的执行时间有可能相同、有可能运行在相同SM上
CUDA 编程模型要求线程块可以按任意顺序并行或串行执行
不使用__syncthreads()的情况下，warp之间的执行不保证同步

每SM的CTA数量 被称为CTA occupancy，一个SM的CTA数量大小由单个CTA所需资源的多少决定
某一时刻下，GPU上并行执行的所有CTA的集合称为wave
wave的size被每SM的CTA数量和kernel占用率影响

L2 cache（ltc - level two cache）

负责执行缓存、压缩、全局原子操作等

其缓存工作可以在一个LTS（level two cache slice）上理解：
LTS即为L2 cache slice（L2缓存子分区），L1TEX miss后，LTS的工作分为tag stage和data stage；
tag stage负责判断该次访问是miss还是hit
data stage负责返回数据（hit）或通过memory controler与DRAM交互（miss）

Nsight Compute中对应的指标
lts__t 对应 Tag stage
lts__m 对应 Miss stage
lts__d 对应 Data stage

L1 data cache

一个SM有一个L1 data cache，在某个SM上执行的属于同一CTA的threads，可以共享一块内存空间，该空间对应
L1 data cache上的某一小部分区域

用户管理的Shared Memory 与 L1/TEX Cache 底层上共用一块物理内存
L1 data cache、shared data cache、Texture data cache are one and the same.

L1 data cache从SM和TEX两个单元接收request；具体而言，从SM接收global和local memory requests，从TEX接收texture和surface requests。
上述request对应的访存操作访问的均为global内存空间

L1 data cache接收到requests后，根据请求类型的不同各自在load/store unit或unit related to texture access进行tag stage和data stage

  • 访问SMEM的requests经过input接口进入后，由于用户管理的Shared Memory 与 L1/TEX Cache 底层上共用一块物理内存，故不存在缓存未命中的概念，此时直接返回
  • 访问global/local的requests经过input接口进入后，依次经历tag stage和data stage，hit则直接通过LSU data pipeline返回，miss则从L2得到数据后再返回
  • 访问texture/surface的requests经过input接口进入后，依次经历tag stage和data stage，hit则直接通过TEX data pipeline返回，miss则从L2得到数据后再返回

lsu - load/store unit
lsuin - load/store unit input

Nsight Compute中对应的指标
l1tex__lsuin_*：观察 LSUIN 的请求入口活动
l1tex__texin_*：观察 TEXIN 的请求入口活动
l1tex__data_pipe_lsu_*：观察 LSU Data 数据通路的活动
l1tex__data_pipe_tex_*：观察 TEX Data 数据通路的活动
