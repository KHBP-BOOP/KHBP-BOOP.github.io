CUDA

2026-05-14

“HPC is all about reducing data movement”.

Roofline

计算平台算力上限（每秒可执行的最大浮点运算数量）- $\pi$

计算平台广义内存带宽上限（内存每秒可交换的最大数据量）- $\beta$

计算强度上限 - $\pi$ / $\beta$

自变量$I$ ： 程序计算强度。
计算公式：

单个样本在程序中发生的浮点运算总数 /

单个样本在程序中需进行的内存交换总量

因变量$P$ ： 程序在计算平台上的每秒浮点运算次数，程序的理论性能值。

$$
P = \begin{cases}
\beta \cdot I, & \text{when } I < I_{\max} \quad \color{red}\text{Memory Bound} \
\pi, & \text{when } I \geqslant I_{\max} \quad \color{green}\text{Compute Bound}
\end{cases}
$$

Tiling

Tiling（分块） 优化的核心标志是使用 共享内存（shared memory）。

它的主要目的是为了数据复用。如果一个数据被加载后，不仅当前线程要用，隔壁线程也要用（比如矩阵乘法、图像卷积、算滑动平均），我们就会把这一块数据先“搬”到片上的共享内存里缓存起来，避免大家反复去排队读取慢速的全局内存

GRAMMAR

Kernel 函数的约束：

返回类型必须是 void
不能使用可变参数（variadic）
不能是类的虚函数
不能递归（Compute Capability < 2.0，现代 GPU 均已支持）
参数通过值传递，指针必须指向设备内存

内存

线程块中：

不同warp内线程间的通信和同步：片上共享内存 on-chip shared memory 由__syncthreads()内部函数实现，该函数会阻塞线程块内的所有线程，直到所有线程都执行到该函数。

同一warp内线程间通信与同步：寄存器 shuffle原语

同一个Cluster内、不同线程块的线程间的通信和同步：分布式共享内存 Distributed Shared Memory

kernel 中的局部变量默认分配在寄存器，单个线程用的寄存器越多，sm上能并行执行的warp就越少（即occupancy会下降）；如占用数量超过寄存器数量，则会溢出至GPU全局内存，速度骤降
实际应用中，先保证没有寄存器溢出，再考虑 Occupancy

一个网格中的每一个线程运行同一个kernel，根据变量的类型，

shared memory warp warp …
32 bank 32 threads 32threads …

虽然同一个 Warp 内的线程可通过__syncwarp()实现同步，但指令同步不等于数据可见。如果数据被锁死在私有寄存器里，其他线程无法访问

片上缓存即GPU芯片内部存储空间，主要包括：
寄存器文件
L1 cache 共享内存
L2 cache

bank conflict

每一个 Bank 在同一时刻只能处理一个地址的请求
broadcast 属于 两个或多个线程访问同一bank的同一处地址 的情况

CUDA 编程模型要求线程块可以按任意顺序并行或串行执行

单指令多线程（Single Instruction, Multiple Threads, SIMT）是专门为GPU设计的并行计算模式。在统一的指令流控制下，多个线程在不同的数据上并行执行相同的操作
不使用__syncthreads()的情况下，warp之间的执行不保证同步
线程块之间的执行顺序不确定

当应用程序启动内核时，它会使用许多线程，通常是数百万个线程

一个线程块（Block）中的线程数量通常为32的倍数，最常见的大小为 128、256 或 512，最大1024
一个grid可能包含数百万个线程块，而执行该网格的GPU可能只有几十或几百个SM
CUDA 当前最多允许一个集群（Cluster）内有 8 个线程块

CPU与GPU间的数据传输：

cudaMalloc + cudaMemcpy GPU cudaFree()
cudaMallocManaged 可被CPU/GPU访问。CPU读写时，经PCIe总线转移至系统内存RAM；GPU读写时，经PCIe总线转移至GPU的全局内存 cudaFree()
cudaMallocHost CPU cudaFreeHost() 存放在物理内存中，GPU可通过PCIe总线访问；会占用宝贵的物理内存空间

The cudaMemcpy API is synchronous 即完成拷贝后函数才会返回

variable with managed CPU/GPU free by os
在 CPU 访问 GPU 刚刚修改过的 managed 变量之前，必须调用 cudaDeviceSynchronize() 确保 GPU 计算已完全结束

cudaMalloc 分配的内存始终 256 Bytes 对齐

FLOP

  • FLOPs 算法、模型所需的浮点计算量总和

  • FLOPS 处理器硬件每秒可进行的浮点运算次数

  • FLOP/Byte 每读取、存入一个字节需执行的浮点运算次数，即任务的计算强度；数值越大，说明该任务越偏向于计算密集型；数值越小，说明越偏向于访存密集型（受限于内存带宽）
