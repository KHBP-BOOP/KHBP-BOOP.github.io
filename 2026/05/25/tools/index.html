CMake

cmake_minimum_required()必须写在Root CML（项目根目录下的CMakeList.txt）的第一行
project()通常被建议写在第二行

target是开发者为一个属性的集合指定的名称
property可以是：
target的产物的类型（如头文件的集合、可执行文件、库文件）
源文件
包含目录
target的最终输出文件的名称
……

有一类属性被称为transitive properties（可传播的属性），需要使用PRIVATE、INTERFACE、PUBLIC关键字来设置其传播方式，其他大部分属性则不需要

PRIVATE 指明这一property只可见于对应的target ，不可被继承
INTERFACE 指明这一property只可见于链接了对应target的target

一个可执行文件或库文件的作用域关键字（scope keyword）绝大部分情况下应为PRIVATE，因为其他项目或库通常无需链接它们
源文件仅包含头文件的库的transitive properties的传播方式应为INTERFACE，因为它们会被复制进.cc文件，跟随它们一起构建，无需单独构建

target_include_directories的三种scope：PUBLIC、PRIVATE、INTERFACE：

使用PUBLIC方式添加目录，目标以及链接了该目标的其他目标，编译时均会在指定的目录下寻找头文件；

使用PRIVATE方式添加目录，只有目标编译时，才会在指定的目录下寻找头文件；

使用INTERFACE方式添加目录，只有链接了该目标的其他目标编译时，才会在指定的目录下寻找头文件。

target_link_libraries

调用链接器、借助scope keyword描述target之间的关系

三种scope：PUBLIC、PRIVATE、INTERFACE：

使用PUBLIC方式链接库，编译目标时，目标以及链接了目标的其他目标均会与指定的库链接；

使用PRIVATE方式链接库，编译目标时，只有目标会与指定的库链接；

使用INTERFACE方式链接库，编译目标时，只有链接了目标的其他目标会与指定的库链接。

Nsight Compute

大多数情况下，合并访问针对全局内存而言。
在现代profiler术语中，uncoalesced shared accesses可被理解为probably bank-conflicted；excessive wavefronts意为超额的内存事务，其中wavefronts为memory transaction的另一种说法，同时，该偏正短语含义为：本次内存请求导致了多于*所需最小wavefront数量（通常为1至2个）*的wavefront数

关键指标

wave per SM
如果总 block 数量刚好能被一个完整 wave 的容量整除，那么波数是整数；否则就会出现小数或非整数波数，表示存在 partial wave。
partial wave通常意味着GPU资源利用率的下降，对于执行时间较短的kernel的影响尤其明显

流多处理器效率（SM Efficiency）

每线程的寄存器文件占用量是影响sm occupancy的重要因素。oc高不代表性能一定高，但oc过低总代表较弱的隐藏延迟的能力

kernel replay

保存GPU memory中kernel可被访问的部分的backup；
第一次replay pass后，确定实际被写入的部分，即subset；
之后的每次replay pass，只需将subset restore回原始位置

  • 为什么需要replay？
    单次 pass 能同时采集的硬件性能计数器有限，需要通过多个 replay pass 分批采集不同的 metrics，最终组合成完整的分析结果
  • 每次 replay pass 都需要先恢复 subset？
    使 kernel 每次执行时看到相同的内存初始状态，从而保证不同 pass 获取的 profiling metrics 可以对应到同一次 kernel 执行条件

port端口

GPU 中的很多单元（例如缓存、存储单元、SM 内部某些模块等）会用一个公共的数据端口来同时处理输入流量和输出流量，读和写、进和出可能共用同一个物理端口，而不是各自独立拥有端口。共享这个端口的各条“链路”（可以理解为某一种流量、某一个方向、某一个子通道）单独看，可能利用率都不高，远没有达到它们各自的峰值带宽；但是，所有这些链路加在一起的总流量，可能已经把这个共享端口的峰值带宽用满了

当 NCU 显示某个单元的数据端口利用率已经接近峰值时，即使各个子链路利用率不高，也不能认为没有瓶颈，需要关注的是端口级别的聚合带宽，而不是某一条热点链路的单路带宽
优化方向应该是降低该端口的总流量，例如减少不必要的读写、改善数据复用、调整访问模式以减少对同一端口的争用。

计算分诊指南

自顶向下的关于CUDA kernel性能分析问题的工作流，针对于在NVIDIA GPUs上使用Nsight compute进行分析工作的场景。

nvidia-smi

  • 查看拓扑结构
    nvidia-smi topo -m

  • 仅查看显存
    nvidia-smi –query-gpu=memory.used,memory.total –format=csv

  • 动态查看
    watch -n 1 nvidia-smi

  • 类 top 风格
    nvidia-smi dmon -s pucvmet -d 1

  • 录入日志文件
    nvidia-smi dmon -s pucvmet -d 1 -f file_name.log &
