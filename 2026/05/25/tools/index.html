CMake

CMake的使用围绕CMakeList.txt（有时又称lists file或CML）展开，CML可以向CMake提供指令，说明如何处理所在目录或其子目录中的本地文件和操作

cmake_minimum_required()必须写在Root CML（项目根目录下的CMakeList.txt）的第一行（root CML是CMake configuration过程中完成初始设置的起点）
project()通常被建议写在第二行（告知CMake该软件项目的名称，并做一系列检查以确保环境适合构建软件）

target是开发者为一个属性的集合指定的名称
property可以是：
target的产物的类型（如头文件的集合、可执行文件、库文件）
源文件
包含目录
target的最终输出文件的名称
……

有一类属性被称为transitive properties（可传播的属性），需要使用PRIVATE、INTERFACE、PUBLIC关键字来设置其传播方式，其他大部分属性则不需要

PRIVATE 指明这一property只可见于对应的target ，不可被继承
INTERFACE 指明这一property只可见于链接了对应target的target

一个可执行文件或库文件的作用域关键字（scope keyword）绝大部分情况下应为PRIVATE，因为其他项目或库通常无需链接它们
源文件仅包含头文件的库的transitive properties的传播方式应为INTERFACE，因为它们会被复制进.cc文件，跟随它们一起构建，无需单独构建

-配置
cmake -B
或会污染项目文件结构的内源构建方式
cmake

cmake –build

  • 单配置生成器（如 Unix Makefiles、Ninja）：
    必须在配置阶段就确定构建类型，切换构建类型需要重新configure或更换目录
  • 多配置生成器（如 Visual Studio、Xcode、Ninja Multi-Config）：
    在configure时使用 CMAKE_CONFIGURATION_TYPES 指定配置集合，忽略CMAKE_BUILD_TYPE，一次性生成所有支持的配置
    用户无需重新配置项目，只需在编译时通过 –config 参数指定是 Debug 还是 Release 即可

使用CMAKE_CXX_FLAGS_、CMAKE_CXX_FLAGS_等一系列变量可以自定义相应的编译参数
CMAKE_BUILD_TYPE指定单配置生成器的build类型，其取值对应预设的一组编译参数，是一种映射

target_include_directories的三种scope：PUBLIC、PRIVATE、INTERFACE：

使用PUBLIC方式添加目录，目标以及链接了该目标的其他目标，编译时均会在指定的目录下寻找头文件；

使用PRIVATE方式添加目录，只有目标编译时，才会在指定的目录下寻找头文件；

使用INTERFACE方式添加目录，只有链接了该目标的其他目标编译时，才会在指定的目录下寻找头文件。

target_link_libraries

调用链接器、借助scope keyword描述target之间的关系

三种scope：PUBLIC、PRIVATE、INTERFACE：

使用PUBLIC方式链接库，编译目标时，目标以及链接了目标的其他目标均会与指定的库链接；

使用PRIVATE方式链接库，编译目标时，只有目标会与指定的库链接；

使用INTERFACE方式链接库，编译目标时，只有链接了目标的其他目标会与指定的库链接。

CUDA-GDB

用户需拥有写入和执行 CUDA-GDB用到的文件 的权限

编译时必须向nvcc传递 -g -G 选项。同时这意味着编译优化选项为-O0，即除十分有限的死代码消除相关优化和寄存器溢出相关优化外，不进行其他优化
调试信息会被包含进二进制可执行文件，即该文件体积会变大

nvcc 编译选项

-g
生成host端代码的调试信息，GDB等类似工具依靠它们进行调试

-G
生成device端代码的调试信息，CUDA-GDB依靠它们进行调试。使用该选项会使nvcc避免进行一部分优化。

-lineinfo
生成device端代码的行号信息，可以在性能分析工具中看到源代码。不会降低执行性能

nvcc默认对device端代码使用-O3优化等级（最高优化等级）

-Xptxas 向PTX汇编器工具ptxas传递参数
例：-Xptxas=-maxrregcount=N 指定每个线程可使用的最大寄存器数

nvidia-smi

  • 查看拓扑结构
    nvidia-smi topo -m

  • 仅查看显存
    nvidia-smi –query-gpu=memory.used,memory.total –format=csv

  • 动态查看
    watch -n 1 nvidia-smi

  • 类 top 风格
    nvidia-smi dmon -s pucvmet -d 1

  • 录入日志文件
    nvidia-smi dmon -s pucvmet -d 1 -f file_name.log &

空格实体

&nbsp; (Non-breaking space)：不换行空格，宽度和一个普通空格相同，是最常用的占位符
&ensp; (En space)：半角空格，宽度大约是中文字符的一半，全角字符的四分之一
&emsp; (Em space)：全角空格，宽度大约和一个中文字符相当
&thinsp; (Thin space)：窄空格，宽度较小，用于微调字符间距
